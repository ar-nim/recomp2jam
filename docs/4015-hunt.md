# 4015 `GameStatsUpdate` hunt — new angles (7.55)

Version pin: `AngelO2Jam.exe` 5,029,888 B, sha256 `83a04541…72c823b`.
Method: static analysis only (byte scans + `objdump -d` slices over the
local `install-root/` copy). No disassembly reproduced; no new REA
dossier issued. VA = file + `0x400000`.

## Why the old angles were doomed

4015 is S→C. The client never sends it, so `push 0xFAF` can never hit
(zero `AF 0F 00 00` words image-wide, re-confirmed). A `AF 0F` compare
also misses: the only three `AF 0F` pairs are a lea-offset constant
(file `0x749f`), an indexed-table read (file `0x1c1864`), and a
multiply seed (file `0x1e8b15`). S→C dispatch here is not an immediate
compare — it is a handler family forwarding into a UI event queue (below).

## Angle 1 — UI event-queue (`0x478d50`) consumers: NEGATIVE for 4015

The S→C handler family calls the UI event queue at VA `0x478d50`
(`mov ecx, 0x762b44` + `push 0x11/0x12` + `push <opcode>`). It has 122
callers covering 61 distinct opcodes (decoded from the `push <imm32>`
preceding each call): 1001/1003/1005, 2001–2033, 3001–3013,
4001/4003/4005/4007/4009/4013/4017/4018/4022–4029/4035–4043/4052–4058,
5001–5039. Present: 4007 team-change (file `0x15f595`), 4013
MusicLoaded (file `0x15fa08`), 4017 ScoreSubmission (file `0x15fbc4`),
4018 ScoreCompleted (file `0x15fed7`). Absent: 4011, 4014, 4015, 4016 —
none of the 122 forwarders pushes `0xFAE`/`0xFAF`/`0xFB0`. So the
in-song stats flow (4014 C→S / 4015 S→C / 4016 C→S) is handled outside
the UI-queue family, consistent with peer-life needing game-object
writes rather than a UI refresh.

## Angle 2 — `0x2190`-stride readers outside the tick site: MAPPED

The tick site (VA `0x4eaf00`) scales a slot index by `0x2190` onto base
VA `0x77ee90`. The same scale+base idiom recurs ~164 times across the
net-handler region (files `0x159000`–`0x162000`), i.e. every S→C member
handler touches the 8-seat table — stride alone does not isolate 4015.

## Angle 3 — 4014-adjacent callers: STRONG CANDIDATE (unverified)

Between the 4013 forwarder (ends file `0x15fa10`) and the 4017 handler
(starts file `0x15fba0`) sits exactly one function, at file `0x15fa20`
(VA `0x55fa20`), that matches the expected `GameStatsUpdate` shape:

- Same packet-reader helper as the verified 4007 handler (`0x555d20`):
  reads a u8 slot index (guarded `< 8`, same as 4007 at file `0x176c86`
  idiom) plus a u16 discriminator.
- Branches on the discriminator being `0` vs `1` — the documented
  Life=`0` / Jam=`1` split — into two member-slot setters on base
  `0x77ee90 + index * 0x2190`.
- The two setters are adjacent field writers in the score-word family:
  value-`0` path calls VA `0x5410e0` (file `0x140e0`, writes sub-object
  `+0x2150` = game `+0x3970`, the life-gate/clamp word); value-`1` path
  calls VA `0x5410c0` (file `0x140c0`, writes sub-object `+0x214e` =
  game `+0x396e`, the jam-level word). Direction matches: Life→life
  word, Jam→jam word.
- Forwards a variable (not constant-opcode) 4-push sequence into the
  same `0x478d50` queue, then runs an 8×8 member-refresh double loop
  over the slot table (plausibly the 8 rank bytes, untraced).

## Angle 4 — dispatcher edge: PINNED (subtract + table, not immediate)

Central S→C dispatcher at file `0x158080` (VA `0x558080`) reads the
packet id word at buffer offset 2 into a local and range-splits. The
`0xFAF` immediate never appears because the 4003–4058 family is not
compared one by one: the high branch (file `0x15833d`) subtracts base
`0xFA3` (4003), bounds-checks `0x37`, indexes a byte table at file
`0x158a68`, then an address table at file `0x1589f4`.

For 4015 (`0xFAF`): offset `0xFAF - 0xFA3 = 12`, byte-table entry `6`,
address-table slot `6` lands on the case at file `0x1586bb`
(VA `0x5586bb`), which passes the packet pointer through and makes the
only image-wide relative call into the candidate (call site file
`0x1586bf` → file `0x15fa20`). Even C→S ids in the same span (4004 /
4006 / 4014 / 4016 / …) map to the shared default exit at file
`0x158937`, so they correctly never reach a handler. This explains the
old misses: zero `push 0xFAF`, zero LE32 absolute refs to VA `0x55fa20`,
and only the three known `AF 0F` pairs — all re-confirmed by byte scan.

Pinned call chain (all file offsets, VA = file + `0x400000`):

- Dispatcher `0x158080` → id-word read (buffer+2) → range split at
  file `0x158259` (`cmp 0xFA1`) → high-range subtract at file
  `0x15835f` (`sub 0xFA3`) → tables `0x158a68`/`0x1589f4` → case
  `0x1586bb` → `call` at `0x1586bf` → candidate `0x15fa20`.
- Candidate `0x15fa20`: u8 slot read via packet-reader helper VA
  `0x555d20` (size `1`, file `0x15fa2c`), u16 discriminator read via
  the same helper (size `2`, file `0x15fa3d`), slot guard `< 8` at
  file `0x15fa46`, discriminator `0`/`1` branches at files
  `0x15fa57`/`0x15fa5d`.
- Value-`0` (Life) path calls setter file `0x140e0` (sub-object `+0x2150`
  = game `+0x3970`, life word); value-`1` (Jam) path calls setter file
  `0x140c0` (sub-object `+0x214e` = game `+0x396e`, jam word). Both
  setters are size-`2` field writers through the same `0x555d20`
  helper. Both paths then forward a variable 4-push into UI queue
  `0x478d50` (files `0x15fa8c`/`0x15fac0`) and run the 8×8
  member-refresh double loop (files `0x15facb`–`0x15fb8f`).
